# 음악 파형 슬라이드 편집기 상세 가이드

이 문서는 프로그램을 처음 쓰는 사람도 **무엇을 어디서 하는지**, 개발 파일을 보는 사람도 **각 파일이 어떤 일을 맡는지** 알 수 있도록 정리한 안내서입니다. 일반적인 사용 순서는 저장소의 [README](../README.md)에 있고, 이 문서는 그 동작의 배경과 세부 규칙을 설명합니다.

## 1. 이 프로그램은 무엇을 하는가

음악 파일, 사진, 자막 문구를 시간축에 배치해 하나의 MP4 파일로 만드는 Windows용 편집기입니다. 원본 음악과 사진을 직접 수정하지 않고, 각 파일의 경로와 편집 정보를 프로젝트(JSON)에 저장합니다. 영상 파일을 만들 때만 원본을 읽어 최종 화면과 소리를 합칩니다.

한 문장으로 흐름을 요약하면 다음과 같습니다.

> 음악을 등록해 파형과 길이를 준비하고 → 사진과 글씨를 시간에 배치하고 → 미리보기로 확인한 뒤 → FFmpeg가 MP4로 출력합니다.

프로그램은 Python과 Tkinter로 만든 데스크톱 앱이며, 화면에서 보이는 영상과 실제 내보내는 영상은 같은 합성 규칙을 사용합니다. 네트워크로 미디어를 업로드하지 않고 로컬 PC에서 처리합니다.

## 2. 화면을 읽는 법

화면은 네 영역으로 나뉩니다.

| 영역 | 하는 일 | 쉽게 생각하면 |
| --- | --- | --- |
| 왼쪽 프로젝트 | 가져온 음악·사진 목록을 보여줍니다. 목록에서 타임라인으로 끌어 놓을 수 있습니다. | 재료 보관함 |
| 가운데 미리보기 | 재생 위치에서 보일 화면을 확인합니다. 이미지 위치와 크기도 조절합니다. | 완성 장면 미리보기 |
| 오른쪽 속성 | 선택한 사진·문구·음악 클립의 시간과 표시 설정을 바꿉니다. | 선택한 재료의 상세 설정 |
| 아래 타임라인 | 클립의 시작과 길이, 서로의 시간 관계를 보여줍니다. | 영상의 시간표 |

패널 경계는 끌어서 크기를 바꿀 수 있고, 보기 메뉴에서 패널을 숨기거나 기본 배치를 복원할 수 있습니다. 창 크기·패널 위치 같은 화면 환경설정은 프로젝트 편집 데이터와 별도로 저장됩니다.

## 3. 처음부터 MP4를 만드는 순서

### 3.1 음악 등록

왼쪽의 음악 추가 기능으로 FLAC, WAV, MP3 파일을 등록합니다. 프로그램은 FFprobe로 파일을 읽을 수 있는지와 길이를 확인하고, FFmpeg로 재생·파형 표시용 데이터를 준비합니다. 분석이 끝나면 목록의 상태가 완료 표시로 바뀝니다. 첫 번째로 등록한 음악은 분석이 끝나면 자동으로 타임라인 0초에 놓입니다.

파형은 소리를 10밀리초 단위로 나눈 뒤 각 구간의 가장 큰 진폭을 기록해 그립니다. 파형은 소리의 크기 변화를 보여주는 시각 안내입니다. 음의 높이나 박자를 판독하는 분석은 아닙니다.

같은 음악을 다시 쓸 때는 임시 폴더의 `MusicToVideo_PCM` 캐시를 재사용할 수 있습니다. 캐시는 원본의 경로·크기·수정 시각을 바탕으로 구분됩니다. 프로젝트에 저장되는 것은 캐시 데이터가 아니라 음악 파일 경로와 클립 정보입니다.

### 3.2 사진 배치

JPG, JPEG, PNG 사진을 등록한 뒤 왼쪽 목록에서 이미지 트랙으로 끌어 놓습니다. 첫 사진은 음악이 있어야 배치할 수 있습니다. 새 사진의 기본 길이는 최대 5초이며, 다음 사진이나 영상 끝과 겹치지 않도록 가능한 범위로 줄어듭니다.

이미지 클립은 서로 겹칠 수 없습니다. 사진이 없는 시간은 검은 화면입니다. 사진을 선택한 뒤 미리보기에서 이동을 켜면 드래그로 위치를 바꿀 수 있고, 모서리 핸들이나 `Alt+휠`로 크기를 조절할 수 있습니다. 화면 맞춤·채움·가운데 정렬·초기화 버튼도 있습니다.

이미지 움직임을 켜면 시작 상태와 끝 상태의 가로 위치·세로 위치·배율 사이를 시간에 따라 보간합니다. `smooth`는 처음과 끝에서 천천히 움직이고, `linear`는 일정한 속도로 움직입니다. 전환 효과는 앞 사진과 현재 사진이 빈틈없이 맞닿아 있을 때만 적용됩니다. 즉시 전환, 크로스 디졸브, 검정 페이드, 좌우 슬라이드를 지원합니다.

### 3.3 문구 추가와 편집

타임라인의 `+ 텍스트` 또는 새 텍스트 항목을 사용해 문구를 추가합니다. 기본 표시 길이는 3초입니다. 글씨는 별도 텍스트 트랙에 놓이지만, 텍스트 트랙의 세로 줄은 화면의 앞뒤 순서가 아니라 겹치는 문구를 선택하기 쉽게 배치한 표시입니다. 실제 앞뒤 순서는 속성의 레이어 순서 설정으로 정합니다.

오른쪽 속성에서 문구, 글꼴, 글자 크기와 색, 정렬, 표시 시작·끝, 위치, 너비, 배경의 색·투명도, 외곽선을 바꿀 수 있습니다. 문구 입력은 여러 줄을 지원합니다. Enter는 줄을 바꾸고, Ctrl+Enter 또는 입력창에서 벗어나면 수정 내용을 확정합니다. 문구는 이미지 위에 그려지며, 배경은 반투명하게 설정할 수 있습니다.

### 3.4 타임라인 편집

- 클립 가운데를 끌면 시간 위치를 옮깁니다.
- 폭이 매우 좁은 클립은 Shift를 누른 채 끌어 본체를 이동할 수 있습니다. 드래그 중 시작·끝·길이와 배치 가능 여부가 표시됩니다.
- 클립의 끝부분을 끌면 지원되는 클립의 시작이나 끝을 조절합니다. 이미지의 끝 시각은 직접 입력하거나 속성에서 바꿉니다.
- 시간 눈금·파형을 클릭하거나 재생 헤드를 끌면 미리보기 위치를 바꿉니다.
- Ctrl+휠로 확대·축소하고, Shift+휠로 가로 이동합니다. 전체 맞춤으로 긴 음악도 한 화면에서 봅니다.
- 스냅은 재생 헤드, 클립 경계, 0초, 영상 끝에 가까이 놓을 때 정렬을 돕습니다. 드래그 중 Alt를 누르면 잠시 해제할 수 있습니다.
- Ctrl+Z / Ctrl+Y는 실행 취소·다시 실행, Ctrl+D는 복제, Delete는 선택 삭제, Esc는 진행 중인 드래그 취소입니다.
- `구성 보기`에서 모든 클립과 검은 화면·무음 구간을 시간순으로 확인하고 선택한 클립으로 이동하거나 복제·삭제할 수 있습니다. 영상 끝을 넘는 클립도 표시합니다.

미리보기에서는 텍스트를 끌어 옮기거나 선택 테두리 양쪽 핸들로 너비를 바꿀 수 있습니다. 이미지도 클릭해 선택한 뒤 끌어 이동하거나 모서리 핸들로 크기를 바꿀 수 있습니다.

음악 클립은 원본의 사용할 구간과 타임라인의 시작 위치를 따로 가집니다. 음악끼리는 겹칠 수 없고, 클립 사이 빈 곳은 무음입니다. 오른쪽 속성에서 타임라인 시작, 원본 시작, 원본 끝을 초 단위로 입력할 수 있습니다. 영상 길이는 타임라인에서 가장 늦게 끝나는 음악 클립을 기준으로 합니다. 사진이나 문구가 그 뒤까지 이어져도 음악이 끝난 뒤의 길이를 늘리지는 않습니다.

### 3.5 프로젝트 저장과 다시 열기

파일 메뉴에서 프로젝트를 JSON으로 저장합니다. 음악·사진은 프로젝트 파일 기준 상대 경로로 기록되므로 프로젝트와 미디어를 함께 옮길 때 폴더 구조를 유지하면 다시 찾기 쉽습니다. 경로를 찾을 수 없으면 프로젝트를 열 때 새 파일을 지정해 다시 연결할 수 있습니다. 원본 미디어 파일은 변경되지 않습니다.

이전 v1 프로젝트도 열 수 있습니다. 내부에서 새 클립 구조로 변환하며, 저장할 때는 기존 파일을 덮지 않도록 `_v2.json` 이름을 제안합니다. v1 프로젝트의 사진은 과거 표시 규칙(원본보다 확대하지 않음)을 보존합니다.

프로젝트 JSON은 편집 내용의 저장 파일이지 MP4가 아닙니다. 다른 PC에서 프로젝트를 열려면 JSON뿐 아니라 연결된 음악·사진 파일도 사용할 수 있어야 합니다.

### 3.6 MP4 내보내기

내보내기 창에서 파일명과 폴더를 정하고 영상 만들기를 누릅니다. 같은 이름의 파일은 자동으로 덮어쓰지 않습니다. 진행률을 확인하고 취소할 수 있으며 완료 화면에서 파일명·길이·크기·저장 경로를 확인한 뒤 결과 영상·저장 폴더를 열거나 경로를 복사할 수 있습니다.

기본 결과는 **1920×1080, 초당 30프레임, H.264 영상(yuv420p), AAC 스테레오 오디오(48kHz, 320kbps)**입니다. 사진은 비율을 유지하며, 맞지 않는 공간은 검게 남습니다. EXIF 회전 정보와 투명 PNG도 반영합니다. 기본 Windows 글꼴은 맑은 고딕이며, 요청한 글꼴을 찾지 못하면 대체 글꼴을 사용합니다.

내보내기 때 프로그램은 먼저 프로젝트의 음악을 시간 순서대로 이어 붙이고, 클립 사이 빈 구간에는 무음을 채웁니다. 사진과 문구를 프레임에 합성한 뒤 FFmpeg로 H.264를 만들고 오디오와 결합해 MP4 컨테이너에 저장합니다. 정지 구간은 한 장면을 반복하는 방식으로 효율적으로 만들고, 움직임·전환 구간은 프레임별로 합성합니다. 따라서 긴 움직임 장면은 정지 화면보다 시간이 더 걸릴 수 있습니다.

출력 파일은 임시 파일로 먼저 만들고 변환이 성공한 뒤 최종 이름으로 옮깁니다. 취소나 오류가 나면 임시 출력과 작업용 장면 파일을 정리합니다. 기존 출력 파일, 누락된 미디어, 음악 클립 부재, 저장 폴더 오류는 내보내기 전에 안내합니다.

## 4. 편집 데이터의 기본 개념

프로젝트에는 크게 네 종류의 데이터가 있습니다.

| 데이터 | 뜻 | 예시 |
| --- | --- | --- |
| 미디어 자산(asset) | 원본 파일 자체를 가리키는 항목 | `사진.png` 경로, `음악.wav` 경로 |
| 클립(clip) | 원본을 타임라인 어디에 얼마나 쓸지 정한 항목 | 음악의 원본 5~20초를 영상의 30초 위치에 배치 |
| 프레임(frame) | 영상에서 한 장의 화면을 세는 단위 | 30fps에서는 30프레임이 1초 |
| 샘플(sample) | 디지털 오디오에서 짧은 소리 단위 | 48kHz에서는 1초에 48,000샘플 |

프로젝트 버전 2는 `audio_assets` / `audio_clips`로 음악 원본과 배치를 나누고, `assets` / `images`로 사진 원본과 화면 구간을 나누며, `texts`에 자막 설정을 저장합니다. 시작과 끝은 사진·문구에서 프레임 기준이고 음악에서는 샘플 기준입니다. 이 구분 덕분에 음악의 구간 잘라쓰기와 사진의 프레임 단위 편집이 가능합니다.

| `tests/` | UI 초기 배치 등의 자동 회귀 검증 코드입니다. 실행에는 Tk 데스크톱 환경이 필요할 수 있습니다. |

### 소스 실행과 Windows 배포

소스 실행은 Python 3.10 이상, Tkinter, FFmpeg, FFprobe가 준비된 Windows 환경을 전제로 합니다. 아래 명령은 저장소 루트에서 실행합니다.

```powershell
python -m pip install -r requirements.txt
python music_to_video.py
```

FFmpeg와 FFprobe는 PATH에서 찾거나 프로젝트의 `ffmpeg/bin`에서 찾습니다. 배포 폴더를 만들려면 빌드 요구사항과 FFmpeg 배포 파일(실행 파일, LICENSE, README)이 필요합니다.

```powershell
python -m pip install -r requirements-build.txt
.\build_windows.bat
```

결과는 `release/MusicToVideo` 폴더입니다. EXE 하나만 떼어 쓰는 방식이 아니라 폴더 전체를 함께 배포합니다. 배포 스크립트는 기존 배포 폴더를 교체하므로, 실행 전에 필요한 로컬 변경이나 백업이 있는지 확인해야 합니다.

## 6. 알아두면 좋은 제한

- 파형은 소리의 크기를 보여주며 음악 박자나 음표를 자동 분석하지 않습니다.
- 영상 길이는 음악 타임라인의 가장 늦은 끝으로 정해집니다.
- 이미지가 비는 곳은 검정 화면이고, 음악 클립 사이의 빈 곳은 무음입니다.
- 이미지 전환은 두 이미지가 정확히 이어져 있을 때 동작합니다.
- 글꼴 대체, 누락 파일 재연결, 출력 파일 충돌은 오류가 아니라 복구 안내 흐름입니다.
- 사진 움직임이 많거나 해상도가 큰 프로젝트는 프레임마다 합성할 작업이 늘어 내보내기 시간이 길어집니다.
- 프로젝트 파일은 미디어를 내장하지 않습니다. JSON만 복사하면 원본 경로를 사용할 수 없을 수 있습니다.

## 7. 코드 흐름을 따라가며 배우기

코드를 읽어보고 싶다면 아래 순서가 이해하기 쉽습니다.

1. `music_to_video.py`의 `main()`을 보면 앱이 어느 모듈에서 시작되는지 알 수 있습니다.
2. `editor_ui_v2.py`의 `EditorApp.__init__()`을 보면 기본 화면을 만든 뒤 v2 기능을 붙이는 구조를 볼 수 있습니다.
3. `choose_audio()`와 `_analyze_asset()`은 음악 등록이 백그라운드 분석으로 이어지는 과정입니다.
4. `place_asset()`, `place_audio()`, `add_text()`는 라이브러리 재료를 타임라인 클립으로 만드는 곳입니다.
5. `render_preview()`와 `editor_core.py`의 `render_scene()`을 비교하면 미리보기와 출력이 공통 합성 규칙을 쓰는 방식을 볼 수 있습니다.
6. `start_export()` / `_begin_export()`에서 UI가 작업 스레드를 시작하고, `editor_core.py`의 `export_video()`가 실제 MP4를 만드는 흐름으로 이어집니다.
7. 저장 형식을 이해하려면 `fresh()`, `save_project()`, `load_project()`, `migrate_v1()`을 읽으면 됩니다.

`editor_ui.py`는 현재 UI가 상속해 쓰는 공통 기반 코드라 여전히 실행 경로에 포함됩니다. 실제 앱 진입점이 `editor_ui.py`를 직접 실행하는 것은 아닙니다.
